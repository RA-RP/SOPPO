# `work/exp/`：单次实验与原始证据

本目录保存实际执行记录。每次实验必须新建一个独立目录：

```text
exp-YYYYMMDD-NN-short-name/
```

一次重跑若改变随机种子以外的重要条件，或意在回答不同问题，应使用新的 experiment ID。不要把多次不同实验混入同一目录。

## 创建与执行门禁

- 只有实验设计已明确通过、`../code/CODE_OVERVIEW.md` 已记录代码交接完成，且用户明确确认该代码版本可以提交服务器后，才能为该设计创建单次实验目录。
- 未获授权时不得用“占位实验目录”、预检、smoke 或 pilot 绕过门禁；设计草案只保存在 `../human_read/exp/`。
- 每个实验 README 必须记录理论批准、实验设计批准、代码版本、代码交接确认与服务器执行授权的版本和日期。任一字段缺失，状态只能为 `LOCKED`，不能提交任务。
- 服务器运行结束后，先同步白名单摘要与远程证据索引并进入 `RESULT_HANDOFF`；未完成用户交接前不得据此启动下一轮实验。

## 每个实验目录的最低要求

- `README.md`：使用同级的 `EXPERIMENT_RECORD_TEMPLATE.md`，记录目标、假设、cycle ID、代码版本、命令、环境、配置、状态和结果摘要。
- 配置快照：保存运行时的最终生效配置，而不只是默认配置。
- 原始证据索引：说明日志、指标、检查点、图表和异常记录的位置；大文件可位于外部存储，但必须留下稳定路径或获取方式。
- 复现信息：随机种子、数据版本/切分、依赖或容器信息、硬件和关键运行时间。

## 边界与维护

- `../human_read/exp/current_experiment.md` 描述“为什么做、如何判定”；这里描述“实际怎样运行”。
- `../human_read/result/current_result.md` 负责跨运行的人类可读解释；这里保留事实、日志和最小摘要。
- 实验完成后不修改原始配置和原始结果来美化结论。需要修复时新建实验，并在两者间交叉引用。
- 无效、失败或中断的运行不得静默删除；记录失败阶段、错误摘要和是否消耗了有效资源。
- 后续单次实验目录继承本规则，不需要重复放置 `AGENTS.md`。

## 本地记录边界

- 实验执行、环境检查、测试、数据处理、模型加载、评价和聚合全部发生在服务器。
- 本地实验目录只保存 README、最终配置文本、服务器环境摘要、数据/代码校验值、任务状态、聚合指标/图表和远程产物索引。
- 数据集、私有标签、tokenized cache、模型/adapter/checkpoint、逐样本预测、embedding、包目录、虚拟环境和含样本文本的原始日志只保留在服务器。
- 本地不得为复核结果而运行分析脚本；应在服务器生成新的聚合摘要，再把白名单产物回传。
