# `result/`：实验结果与解释

本目录维护三个内容文件：

- `current_result.md`：进入结果阶段后保存当前轮结果、解释和结论边界；此前只保留锁定模板。
- `useful_results.md`：经复盘后认为可用于论文的历史结果。
- `result_archive.md`：所有实验结果，按 cycle/experiment ID 追加。

## 阶段门禁与交接

- 只有实验设计已获明确批准、`CODE_IMPLEMENTATION` 已完成并经用户确认、服务器执行已获授权，且服务器已经返回可核验的白名单结果摘要（或终止/失败摘要）与远程证据索引后，才能进入 `RESULT_HANDOFF`。
- 结果讨论按“执行完整性 → 观察事实 → 与预先判据比较 → 解释与替代解释 → 结论边界”进行；不得在证据缺失时用预期补齐。
- 结果交接完成需要同时满足：`current_result.md` 已完成、完整快照已归档、执行偏差和证据路径已说明，并且用户明确确认已完成交接。
- 用户仅阅读、提问或未提出异议不算交接完成。未记录明确确认前，`../nextCycle/` 保持锁定。
- 即使实验失败、提前终止、结果为负面或无法判断，也必须完成同样的结果交接。

## 更新规则

1. 先核对 `../../exp/<experiment_id>/` 中的配置和原始证据，再撰写结果；不能只根据预期或零散日志下结论。
2. `current_result.md` 明确区分：观察事实、统计不确定性、解释、替代解释、异常和结论。
3. 结果完成或解释发生实质修改时，将完整快照追加到 `result_archive.md`。
4. 失败、负面和无结论结果同样进入归档；说明它排除了什么、没有排除什么。
5. 只有能够支撑论文论点、关键消融、重要负面发现或方法选择的结果才进入 `useful_results.md`，并链接配套设计与原始证据。
6. 结果本身不直接改写理论；先记录证据，再在 `../nextCycle/current_plan.md` 中决定如何处理理论。
7. `current_result.md` 必须记录理论版本、实验设计版本、代码版本/校验值、代码交接与执行授权、进入条件核验、当前阶段、结果交接状态和用户确认日期。

## 本地解释边界

- `current_result.md` 只能依据服务器生成的聚合 Markdown/JSON/CSV、汇总图表、配置与远程证据索引撰写。
- 本地不得下载或加载数据集、私有标签、模型、checkpoint、逐样本预测或 embedding，也不得运行统计、评价或绘图代码。
- 如果需要新的切片、区间、图表或误差分析，先新增服务器聚合任务；本地只接收其无样本级内容的汇总结果。
- 结果记录必须分别列出“本地已回传摘要”和“服务器保留原始证据”，保证证据可追溯但不复制到本地。
