# `nextCycle/`：下一轮决策

本目录维护三个内容文件：

- `current_plan.md`：结果交接完成后形成的下一步行动；此前只保留锁定的历史预置草案或模板。
- `useful_plans.md`：预计会体现在论文叙事中的历史规划与关键决策。
- `plan_archive.md`：所有规划版本，按 cycle ID 追加。

## 阶段门禁

- 只有 `../result/current_result.md` 已完成归档，并记录用户明确确认结果交接完成后，才能进入 `NEXTCYCLE_DISCUSSION`。
- 在门禁打开前，既有规划只能作为锁定的历史预置草案，不得据此修改下一轮理论、设计实验或授权执行。
- 本阶段与用户讨论证据如何影响理论以及下一轮优先级；用户沉默、未反对或继续提问不等于通过规划。
- 用户明确通过 `current_plan.md` 后，记录规划版本和确认日期，创建新的 cycle ID，并回到新一轮 `THEORY_DISCUSSION`；不能从规划直接跳到实验或服务器执行。
- 如果结果解释被重新打开，当前规划立即重新锁定，直至结果再次完成交接。

## 更新规则

1. 只有在结果交接已获用户明确确认后才形成当前规划；仅阅读 `../result/current_result.md` 不足以解锁。如果结果尚不充分，明确把下一步写成补证据而不是提前确认理论。
2. `current_plan.md` 必须说明：证据摘要、对理论的处理（保留/修订/放弃/待定）、候选行动、优先级、选择理由、成功条件和资源约束。
3. 规划定稿或发生实质修改时，将完整快照追加到 `plan_archive.md`。
4. `useful_plans.md` 只收录影响论文方法、实验路线或叙事的关键决策，写明当时证据与事后评价，避免事后合理化。
5. 下一轮开始后，先把被采用的行动转化为新的 `../theory/current_theory.md` 修订并完成理论门禁；不能直接形成或执行新的实验设计。之后仍按 `EXP_DISCUSSION → CODE_IMPLEMENTATION → SERVER_EXECUTION` 推进，并保持 cycle ID 可追溯。
