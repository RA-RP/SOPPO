# `theory/`：理论

本目录只维护两个内容文件：

- `current_theory.md`：最新且自洽的完整理论版本。
- `theory_changelog.md`：按 cycle ID 追加理论变化过程。

## 阶段门禁

- 本目录对应 `THEORY_DISCUSSION`，是每个 cycle 的唯一入口；当前理论未获用户明确通过前，不得进入实验讨论，更不得进入代码实现、上传或运行实验。
- 与用户逐段阅读、回答问题和按反馈修订，均仍属于理论讨论，不应据此推断“已通过”。
- 退出本阶段时，在 `current_theory.md` 记录理论版本、确认日期和“用户已明确通过”；只有这条记录才能解锁 `../exp/`。理论通过不能越级解锁 `CODE_IMPLEMENTATION` 或服务器执行。
- 若已通过的理论发生实质变化，理论状态恢复为“讨论中”，并重新锁定所有下游阶段，直至用户再次明确通过。

## 更新规则

1. 开始新一轮时，结合 `../../../idea/`、`../../../observe/`、`../../../相关工作/` 和上一轮结果修订 `current_theory.md`。
2. 当前理论至少包含：研究问题、符号/定义、机制或推导、关键假设、可证伪预测、与相关工作的差异、`C_{\gamma}` 的角色、适用边界和未解决问题。
3. 在 `theory_changelog.md` 追加“从什么变到什么、为什么变、证据来自哪里、影响哪些实验”的记录。没有理论变化也要写明原因。
4. 理论断言引用来源；来自直觉的判断标为假设，来自实验的判断链接到具体 result 与 experiment ID。
5. 不在本目录写运行命令、原始日志或大段实验结果。
6. `current_theory.md` 的版本信息必须包含当前阶段、用户确认状态和确认日期；待确认时不得填写推定日期或把“待实验检验”混同为“已通过讨论”。
