# `SOPPO/code/`：实现代码

本目录存放当前想法的实现。`CODE_OVERVIEW.md` 是必须持续维护的人类可读代码说明，也是阅读代码前的首要入口。

## `CODE_IMPLEMENTATION` 阶段门禁

- 本目录承担独立的 `CODE_IMPLEMENTATION` 阶段，把已批准实验规范转化为源码、配置和服务器脚本；不是服务器执行阶段的附属步骤。
- 只有 `../human_read/exp/current_experiment.md` 已记录用户明确通过具体实验版本后，才能开始本轮实现。理论通过或实验草案存在都不足以解锁代码。
- 本阶段所有代码文件写在本目录树中；不得把项目实现写入 `human_read/`、单次实验记录或本地临时目录。
- 本地只允许编写/修改源码、shell、YAML/JSON 配置、Markdown，以及进行不导入项目、不接触数据/模型的静态文本检查；不得安装、导入、运行、测试、smoke 或使用 GPU。
- `CODE_OVERVIEW.md` 是本阶段的当前说明与交接文件，必须逐项说明“实验规范 → 配置/模块/入口/输出”的映射，并记录代码版本或静态校验值、未验证项和服务器验证计划。
- 只有实现与说明完成，并且用户明确确认当前代码版本可以提交服务器后，才能退出本阶段；该确认同时形成服务器执行授权。没有这条确认不得 SFTP 上传、创建实验目录或启动任务。
- 实现实质偏离获批设计时，立即停止，返回 `EXP_DISCUSSION` 记录并重新获得实验批准；不能在代码中静默改变研究问题、对照或判断标准。
- 服务器发现纯实现缺陷时返回本阶段修复并形成新代码版本；若修复改变实验语义，则继续退回 `EXP_DISCUSSION`。每次重新提交服务器前都要更新代码交接状态。

## `CODE_OVERVIEW.md` 必须覆盖

1. 当前研究目标与实现边界。
2. 功能模块、关键文件/符号及模块之间的数据流。
3. 训练、评估、观测和数据处理入口及最小运行方式。
4. 超参数的名称、含义、类型、默认值、作用阶段和合理范围。
5. 输入、输出、检查点、日志和指标的存放位置。
6. `C_{\gamma}` 观测方法的实现位置、接口、计算时机和与旧项目的差异。
7. 代码版本与实验标识的对应关系、已知限制和待完成项。
8. 获批实验规范到代码的逐项追踪表、静态复核结果、服务器待验证项、代码交接状态与用户确认日期。

## 更新规则

- 新增、删除或重命名功能模块时，同步修改模块表和执行流程。
- 改变默认超参数、参数语义、命令行入口、配置优先级或输出格式时，在同一次变更中更新说明。
- 区分“代码默认值”与“某次实验的覆盖值”；后者只在 `../exp/<experiment_id>/` 记录，并从总览链接过去。
- 文档以解释“为何存在、如何连接、如何复现”为主，不逐行复述代码。
- 尚未实现或尚未核验的内容明确标记为 `待实现` 或 `待核验`，不得用未来计划描述成现状。
- 后续新增源码子目录默认继承本规则，不因目录增多而重复创建同内容的 `AGENTS.md`。
- `CODE_OVERVIEW.md` 必须显示当前研究阶段、实现是否解锁、所依据的获批理论/实验版本、代码交接状态、用户确认日期和服务器执行授权。

## 本地编辑与远程执行边界

- 本地可以创建和修改源码、shell 脚本、配置与文档，但不得导入或执行项目代码来验证修改。
- 本地不得安装依赖、创建环境、下载模型/数据，或运行 formatter/linter/test，只要该工具需要额外包、导入项目、读取样本或加载模型。
- 单元测试、集成测试、数值/梯度测试、环境预检、smoke、训练、评价和聚合全部通过 `../../machine/` 中定义的服务器任务完成。
- 文档中的命令必须明确标注为服务器命令；不能建议用户在本地运行训练入口或测试入口。
- 服务器生成的 package/environment、模型、数据、checkpoint 和逐样本输出不回传到本目录。本目录只记录接口、默认参数和服务器产物位置。
